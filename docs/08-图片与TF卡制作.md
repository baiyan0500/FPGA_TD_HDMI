# 图片与 TF 卡制作

工程按**物理扇区**扫描 TF 卡，不依赖 FAT 目录项。因此普通“删除文件”不会真正移除图片数据，旧图可能被再次识别。换素材必须按本文流程处理。

## 1. 图片转换

脚本：`doc/convert/convert_images_to_bmp.py`（需要 Python 3 + Pillow）

```bash
pip install Pillow
```

### 批量模式

1. 把原始图片（jpg/png/webp/gif 等）放入 `doc/convert/input_images/`
2. 运行：

```bash
cd doc/convert

# 默认缩放到 640x480
python convert_images_to_bmp.py

# 保持原尺寸，只转成 24bit BMP；超过 1024x2047 时等比缩小
python convert_images_to_bmp.py --keep-size
```

3. 生成的 BMP 位于 `doc/convert/output_bmp/`，文件名会带实际尺寸（如 `1_1024x577.bmp`）

### 单文件模式

```bash
python convert_images_to_bmp.py input.jpg output.bmp
python convert_images_to_bmp.py input.jpg output.bmp --keep-size
```

脚本会用 LANCZOS 缩放并去除 Alpha 通道。默认输出 640×480；`--keep-size` 保留原图尺寸（上限 1024×2047），由固件缩放到 640×480 显示。若原图本身满足工程要求，也可以直接使用，不必转换。

批量模式启动时会先删除 `output_bmp/` 里上一次生成的 `*.bmp`，避免换图后旧输出继续被同步到卡上。

## 2. 写入 TF 卡

脚本：`doc/convert/sync_to_sd.py`

> **注意**：脚本会清零并删除卡内所有可见文件，最后只复制 BMP。**卡上的 WAV 也会被删除**，请在同步完成后单独把 WAV 复制到卡根目录。

```bash
# 假设 TF 卡为 E:
python sync_to_sd.py E:

# 指定源目录、同步 16 张
python sync_to_sd.py E: -s "doc/convert/output_bmp" -n 16
```

如果这张卡以前**手动删除过图片**（没有经过脚本清零），先做一次深度清理：

```bash
python sync_to_sd.py E: --deep
```

`--deep` 会用零数据覆盖前 512MB 空闲空间后再删除（固件只扫描前 128MB，512MB 已足够），耗时数十秒到数分钟，能清掉“目录项已消失、物理扇区仍有 `BM` 头”的历史残留。日常换图不需要每次加 `--deep`；需要更大范围时可用 `--deep-mb 1024`，`--deep-mb 0` 表示填满整张卡（很慢）。如果加 `--deep` 后仍显示旧图，直接对卡做一次**完整格式化**（取消“快速格式化”）再同步，这是最彻底的方式。

脚本行为：

1. 遍历卡上可见文件，对 `.bmp` / `.wav` 先用 0 覆盖全部内容，再删除；其他文件直接删除
2. `--deep` 时再写零填充文件覆盖前 512MB 空闲空间并删除，清除以前手动删除留下的扇区残留
3. 从源目录按文件名排序取前 N 张（默认 6），加 `00_`、`01_` 前缀写入
4. 逐张检查 `BM` 魔数、24bit、未压缩、正高度、宽高上限，不合格会给出警告

> **物理连续性**：固件按“文件长度”跳扇区读取，要求**每个 BMP 在卡上物理连续**。exFAT 在存在空闲碎片时可能把文件拆成多段（`shutil.copy2` 分块写入尤其容易命中），后段会花屏甚至跳过整张图。写入后可用
> ```bash
> fsutil file queryextents F:\00_xxx.bmp
> ```
> 检查，每个文件应只有一行 `VCN: 0x0`。若出现多段，删掉该文件后用一次性写入重写（例如在资源管理器里复制，或 `python -c "open(r'F:\\x.bmp','wb',buffering=0).write(open(src,'rb').read())"`），再复查 extent。

完成后：

```text
E:\
├── 00_xxx.bmp
├── 01_xxx.bmp
├── ...
└── your_audio.wav     # 同步后手动复制
```

**换图后必须给开发板断电重新上电**（或重新下载 bit 触发复位）。固件只在初始化时扫描一次；只按 K2 只会在已经缓存的图片列表里切换。

## 3. 固件侧限制

| 项目 | 限制 |
|---|---|
| 扫描范围 | 前 128MB（扇区 0~262143），4KB 步进，扫满为止 |
| BMP 数量 | 最多 16 张，按物理扇区顺序播放 |
| BMP 格式 | 24bit、未压缩、自底向上；宽 ≤1024、高 ≤2047 |
| WAV 数量 | 仅第一个被扫描到的 WAV |
| WAV 格式 | PCM 16/24/32bit（含 `WAVE_FORMAT_EXTENSIBLE` 子格式 PCM）、mono/stereo、8k/11.025k/16k/22.05k/24k/32k/44.1k/48k |
| 文件系统 | FAT32 / exFAT 均可；固件按物理扇区扫描，不依赖目录结构 |
| 中文文件名 | 固件不解析文件名，仅影响 PC 端排序 |

## 5. 视频容器（EGV）

视频封装成 EGV1 裸扇区容器：首扇区是容器头（分辨率/帧率/每帧块大小/音轨参数/物理段表），后续按 201 扇区/帧交织视频与音频。

```bash
# 1) 生成容器（同时回填 src/user_source/hdl_source/video/egv_cfg.vh，仅作兜底常量）
python tools/video/mp4_to_egv.py 素材.mp4 E:/VIDEO.EGV

# 2) 检查物理簇是否连续
python tools/video/exfat_check.py E:

# 3) 烧录本版 bit 即可；换视频/重建卡不需要重新综合
```

本版固件在扫描阶段按 `EGV1` 魔数找到容器起始扇区，首次播放前用 CMD17 读一次容器头，**动态装载物理段表与帧数**，因此：

- 换视频、重建卡后**无需重新综合**，只要容器起始扇区落在前 128MB 扫描窗口内、且按 4KB 对齐（exFAT 簇 ≥4KB 时自然满足）
- 头部校验失败或扫描窗口内没找到容器时，回退到 `egv_cfg.vh` 的编译期段表（旧行为）；此时画面错位/音轨异常说明容器位置或内容与 bit 不匹配，应先确认 EGV 在 128MB 内、物理连续（用 `node tools/video/egv_locate.js 1 VIDEO.EGV` 自检）
- 写入顺序仍建议 **先同步 BMP/WAV，再写 EGV 容器**：容器接近 200MB，先写会把后续图片挤到 128MB 扫描窗口之后
- 视频层只在 SW1/SW2 拉低、SW3 拉高时生效，K1 播放/停止

更换视频的完整流程：

1. 在 PC 上删除卡里的旧 `VIDEO.EGV`
2. 重新运行 `mp4_to_egv.py`（顺带回填 `egv_cfg.vh` 兜底常量）
3. 把新容器写到卡上（放在图片/WAV 之后），断电重新上电，SW3 层按 K1 播放
4. 只有需要走编译期回退路径时，才需要重跑 TD 综合 + Multi-Seed 并重烧 bit

## 6. 常见问题

**直接放 PNG/JPG 不显示**

固件只解析 24bit 未压缩 BMP 的 `BM` 头，不会解码 PNG/JPEG；把后缀改成 `.bmp` 也没用。必须用转换脚本或图片工具真正保存为 BMP。用 `--keep-size` 可以保留 1024 宽度，只做格式转换。

另外固件固定输出 640×480，非 4:3 图片会被拉伸填满；介意比例时先把图片裁剪/加边到 4:3（如 1024×768）再转换。

**显示旧图 / 卡死**

固件按物理扇区找图，Windows 的“删除”和“快速格式化”都不会清掉扇区里的旧 `BM` 头。按下面顺序处理：

1. `python sync_to_sd.py E: --deep` 做一次深度清理（会覆盖空闲簇）
2. 确认 `output_bmp/` 里没有旧图；批量转换现在会自动清空旧输出
3. 同步完安全弹出，给开发板**断电重新上电**，不要只按 K2
4. 仍然出现旧图时，对卡做一次**完整格式化**（取消“快速格式化”），再重新同步
5. 图片必须是 24bit、未压缩、自底向上 BMP，否则用转换脚本重新生成

**一张图都不出，显示 `NO IMAGE ON SD`**

固件按 4KB 步进扫满前 128MB（扇区 0~262143），中途不会因为“空档太长”提前收工。所以：

- 图片必须在**前 128MB 之内**。EXFAT/FAT32 卡的数据区前面有 FAT 表、分配位图等元数据（本项目的 exFAT 卡占前 16.8MB，第一张图从扇区 34048 开始），这是正常的，不影响扫描
- 直接把图片拷到卡上时，Windows 会分配到第一个空闲簇，通常就在数据区开头；但如果是往里补充文件、或卡上已有大量数据，图可能落到 128MB 之后，固件就扫不到
- 图片必须是 24bit、未压缩、自底向上 BMP（宽 ≤1024、高 ≤2047），否则即使被识别也会跳过
- 换图后必须**断电重新上电**：扫描只在初始化时做一次

**没有声音**

- WAV 不是 PCM（或 EXTENSIBLE 子格式不是 PCM），位深不在 16/24/32bit，或采样率不在支持列表
- WAV data 位于 128MB 扫描窗口之外
- 卡上同时存在多个 WAV，固件只取第一个
- 检查 SW3 层 K1 是否处于暂停状态

**图片顺序不对**

- 固件按物理扇区顺序读取，不按文件名。用 `sync_to_sd.py` 加序号前缀写入

**只显示部分图片**

- 单张 BMP 超出前 128MB，或图片损坏/截断。减少数量或缩小文件

**视频花屏 / 错帧 / 只播几秒**

- 容器位置不对：本版固件按 `EGV1` 魔数在**前 128MB**内找容器，找不到则回退编译期段表（旧 LBA，几乎必然错位）。重新封装/搬动视频后让容器仍落在 128MB 内并保持物理连续
- 卡上文件碎片过多：`exfat_check.py` 检查；文件被拆成超过 4 段时运行时段表会拒绝，回退编译期常量，需先整理卡
- 视频层只在 SW1、SW2 拉低、SW3 拉高时生效，K1 才是播放/停止
