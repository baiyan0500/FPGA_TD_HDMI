# 功能与操作

## 1. 上电流程

1. 插入已准备素材的 TF 卡，连接 HDMI 显示器/电视
2. 上电后等待三个 PLL 锁定 + 20ms POR，约数百毫秒内出现开机画面
3. 系统扫描 TF 卡前 128MB（扇区 0~262143，4KB 步进，扫满为止），最多记录 16 张 BMP 和第一个 WAV；命中 `EGV1` 魔数时记录容器位置并直接跳过整个容器
4. 首张图片写入 SDRAM 完成后，启动面板消失，进入正常播放；WAV 校验通过则自动开始播放
5. 未检测到有效图片时保持黑屏；未检测到有效 WAV 时自动使用内置测试音
6. 视频不在上电时读取：SW1、SW2 拉低、SW3 拉高后按 K1 才开始从 EGV 容器取流
7. SW4 是独立的告警覆盖开关：任意时刻拉高都会**全屏**进入告警态（压暗染红 + 上下 45° 警示斜纹带 + 居中告警卡片），拉低即恢复，不影响当前功能层

## 2. 显示与 OSD

- 输出：640×480@60，HDMI 1.4b，24bit RGB
- 上下信息栏保持原例程布局：顶部状态/标语、底部时间戳与模式信息
- 开机阶段：左中区域显示 `FPGA DISPLAY SYSTEM`，右侧显示 SW/K 功能说明，左侧边框有跑马灯效果；首图提交后恢复常规显示
- 常规 OSD：亮度/对比度（显示为 `20%/40%/60%/80%/100%`，不再是 1~4 档号）、转场模式、自动轮播状态、播放计数、音量峰值条、32 段频谱（按开关显示）
- 频谱/音量条均为**全宽透明叠加**：柱条直接盖在画面上，不带黑色背景框
- 弹幕：两条轨道从右向左滚过画面（层3 K2 控制开关）
- 资源面板：LUT/FF/RAM/DSP 占用条 + 视频帧号与播放状态（层3 K4 控制开关）
- 告警覆盖层（SW4=1）：**全屏接管**，显示优先级高于启动面板、上下栏、弹幕、资源面板与频谱，SW4 拉低立即消失。整屏分四层：
  1. **底图**：视频压到 1/4 亮度再叠一层脉动暗红（`R = 0x14 + 呼吸值/4`），画面整体进入告警色调；
  2. **上下警示带**：屏幕顶部与底部各 56px 的 45° 黄黑斜纹带，条纹随呼吸横向流动；
  3. **告警卡片**：居中 464×168（x 88..552 / y 160..328），4px 红色边框 + 距外沿 10px 的 2px 琥珀内线 + 深红底；
  4. **文字**：4 倍字号 `WARNING`（208..432 / y 176..208）+ 4 行 2 倍字号说明 `EMERGENCY ALERT` / `SYSTEM IS IN DANGER` / `ACTION REQUIRED NOW` / `CHECK THE EQUIPMENT`（行距 24px）。
  呼吸值逐帧三角波（0→255→0，约 2.1s 一周期）：边框、标题颜色与斜纹相位同步脉动
- 视频：320×148 源画面横向/纵向各放大 2 倍，居中占据 640×296（第 92~387 行），上下各 92 行黑边
- 标语默认 `EG4S20 HDMI PLAYER`，可通过 UART 更新；仅支持 ASCII 字符

## 3. TF 卡与素材要求

### 3.1 扫描方式

工程**按物理扇区扫描**，不依赖 FAT 目录项：

- 在扇区 0~262143（前 128MB）内查找 `BM`（BMP）与 `RIFF/WAVE`（WAV）标识
- 最多加载 16 张 BMP，按物理扇区顺序播放，**不按文件名排序**
- 只使用扫描到的第一个 WAV
- 删除文件后底层扇区数据仍可能存在，因此换图必须使用 `doc/convert/sync_to_sd.py`；它会在删除前把可见 BMP/WAV 清零，`--deep` 可进一步覆盖历史残留扇区
- 扫描同时识别 `EGV1` 容器魔数：命中后读头里的总扇区数并直接跳过整个容器，容器位置与段表在播放时动态解析（见 3.4），重新封装/搬动后一般无需重烧 bit

### 3.2 BMP 要求

| 项目 | 要求 |
|---|---|
| 格式 | Windows BMP，未压缩（BI_RGB） |
| 位深 | 24bit |
| 方向 | 仅支持自底向上（正高度）；负高度（自顶向下）会被拒绝 |
| 分辨率 | 宽 ≤1024、高 ≤2047；非 640×480 时由 `scaler` 最近邻缩放到 640×480 |
| 大小 | 单张需落在前 128MB 扫描窗口内，起始扇区是 8 的倍数（4KB 对齐，exFAT 簇 ≥4KB 时自然满足） |

推荐直接用 `doc/convert/convert_images_to_bmp.py` 统一转换；默认输出 640×480，加 `--keep-size` 可保留原尺寸（上限 1024×2047）。注意 PNG/JPG 不能直接给固件读取，必须转成 24bit BMP。

### 3.3 WAV 要求

| 项目 | 要求 |
|---|---|
| 编码 | PCM（format=1），16bit |
| 声道 | 单声道或立体声 |
| 采样率 | 8k / 11.025k / 16k / 22.05k / 24k / 32k / 44.1k / 48k |
| 行为 | 解析成功后循环播放；到 data 尾部自动回绕；暂停时冻结读指针，恢复后从断点继续 |
| 回退 | 非 PCM、非 16bit、采样率不支持、无 data 等情况自动回退内置测试音 |

### 3.4 视频容器（EGV1）

视频不是普通文件读取，而是由工具转成带物理段表的裸扇区容器：

| 项目 | 要求 |
|---|---|
| 源文件 | H.264/H.265 等 ffmpeg 可解的 mp4/mkv 均可 |
| 输出 | EGV1 v2 容器：512B 头 + 每帧 201 扇区的块（185 视频扇区 + 16 音频扇区） |
| 画面 | 320×148，RGB565 大端，24fps |
| 音频 | 48kHz 立体声 s16le，每帧 2000 个立体声样本 |
| 帧数 | 当前容器 1928 帧 ≈ 80 秒 |
| 码率 | 约 2.6MB/s，SD 卡读写时钟固定 100MHz |

```bash
# 1) 把 mp4 封成 EGV 容器（同时回填 egv_cfg.vh 作为旧位置兜底）
python tools/video/mp4_to_egv.py input.mp4 E:/VIDEO.EGV
#    可选参数：--width 320 --height 148 --fps 24 --rate 48000

# 2) 写完后核对物理段是否连续（exFAT 碎片会让画面错乱）
python tools/video/exfat_check.py E:
```

容器位置与段表在**运行时**解析：`egv_reader` 在 K1 启动时读取容器头（1 个扇区），直接使用头内的段表（**最多 4 段**，与 `mp4_to_egv.py` 的 `MAX_RUNS` 一致）播放；扫描只负责用魔数定位容器。重新转换/搬动视频后一般**无需重烧 bit**，但头必须自洽：段数 ≤4、各段扇区之和 = 帧数 × 201、run0 物理起点 = 头所在扇区 + 1。不满足时按以下顺序回退：字段合法但起点不符 → 整文件连续读（M_CONTIG）；魔数正确且容器仍在编译期 LBA → 旧编译期段表（M_CONST）；魔数或关键字段不可信 → 保持黑屏（M_NONE），绝不读错误扇区。写入前请先删除卡上旧容器，避免 exFAT 把新文件拆成更多段。

### 3.5 制作与同步

```bash
# 1) 转换图片：把素材放入 input_images/，运行（会先清空 output_bmp 里的旧 BMP）
python doc/convert/convert_images_to_bmp.py
#    想保留 1024 宽度、只转格式：
python doc/convert/convert_images_to_bmp.py --keep-size

# 2) 同步到 TF 卡（假设盘符 E:，默认最多 16 张）
python doc/convert/sync_to_sd.py E:

# 曾经手动删过卡上图片时，先做一次深度清理（较慢）
python doc/convert/sync_to_sd.py E: --deep
```

`sync_to_sd.py` 会清零并删除可见文件、按序号写入新图，避免 FPGA 扫描到残留旧图；写完请**断电重新上电**，固件只在初始化时扫描一次。详细说明见 [图片与 TF 卡制作](08-图片与TF卡制作.md)。

## 4. 按键与拨码

拨码分层：**SW1 高 = 图片层**，SW1 低 + SW2 高 = **自动层**，SW1/SW2 低 + SW3 高 = **视频层**。同一时刻只有一层生效，进入其它层会强制关闭本层的自动轮播/可视化/视频。**SW4 与分层无关**：拉高时在任意功能层上叠加告警覆盖层，不改变按键含义。

| 拨码层 | K1 | K2 | K3 | K4 |
|---|---|---|---|---|
| **SW1 高**（图片层） | 转场模式循环：淡入淡出→右擦除→左擦除→下滑入 | 手动切下一张 | 亮度循环：100→20→40→60→80% | 对比度循环：100→20→40→60→80% |
| **SW1 低、SW2 高**（自动层） | 转场模式循环 | 自动轮播开/关（1 秒/张） | 音频暂停/继续 | 可视化三态：关→音量条→音量条+全宽频谱→关 |
| **SW1/SW2 低、SW3 高**（视频层） | 视频播放/停止 | 弹幕开/关 | 频谱开/关 | 资源面板开/关 |
| **SW4 高（任意层）** | 不改变功能层 | 不改变功能层 | 不改变功能层 | 不改变功能层；**全屏告警**：压暗染红 + 上下警示斜纹带 + 居中告警卡片（4 倍字号 WARNING + 4 行说明），呼吸脉动，最高显示优先级 |
| SW1~SW3 均低 | — | — | — | —（无功能层，仅显示当前图片） |

> 亮度/对比度档位在 OSD 上按百分比显示；切图只在图片层可手动触发，自动层/视频层的 K2 不再切图。

### 启动菜单右面板（CONTROLS）

上电菜单右上方 `CONTROLS / SWITCH FUNCTIONS` 常显三层按键说明，文字与上表一一对应，便于不看文档直接操作：

```
CONTROLS
SWITCH FUNCTIONS
 SW1 IMAGE LAYER ON        ← 行尾 ON/-- 为该拨码的实测电平
  K1 MODE   K2 NEXT
  K3 BRIGHT K4 CONTRAST
 SW2 AUTO LAYER  --
  K1 MODE   K2 AUTOPLAY
  K3 AUDIO  K4 VIZ
 SW3 VIDEO LAYER --
  K1 PLAY   K2 DANMAKU
  K3 SPEC   K4 RESMON
```

- 「ON / --」取自拨码实测电平（`sw` 经两级同步进 `video_clk` 后送 `osd_layer.i_sw`），不是软件层的选中状态，因此能直接看出拨码是否被正确识别；
- 下方 `STATUS` 区第 4 行 `SW:xxxx LT:n OK` 同时给出 4 位拨码原始电平、**当前生效层号**（LT=1/2/3，0 = 无功能层）与**视频帧完整性**，可与拨码行互相印证；
- 帧完整性 `OK/NG` 是本轮新增的上板自证位（`video_frame_fill.o_frame_ok` → `osd_layer.i_vok`）：
  - `OK` = 最近一帧收到的源像素数恰好 320×148 = **47360**，即 SD 读回的视频字节数与容器头声明一致；
  - `NG` = 像素数不足或超出，说明 SD 物理层丢/多字节。此时画面会整体横向循环错位（少 1 个 512B 扇区 = 少 256 源像素 = 屏幕左移 **512** 像素，正好是"左边约 1/5 跑到右边"），音频同时变成电流声；
  - 判读方法：`OK` 且画面仍错位 → 问题在 SDRAM 读侧/显示时序；`NG` → 降 SPI 时钟或查卡；
- 说明文字直接由 `osd_layer.guide_char()` 生成，改按键映射必须同步改这张表（文件内有对应注释）。

### 数码管

- SW2 高：显示 6 位播放计数（`shown_bcd`）
- SW2 低：显示一位 SD 状态码（原例程逻辑）
- 数码管扫描时钟为 50MHz

## 5. UART 标语与弹幕协议

| 项目 | 参数 |
|---|---|
| 波特率 | 115200，8N1，无流控 |
| 电平 | 3.3V TTL（板载 USB-UART） |
| 结束符 | `\n` 或 `\r` |
| 编码 | ASCII，最多 32 字节；超过 31 字符自动滚动 |
| 控制命令 | `left`：从右向左滚动；`right`：从左向右滚动 |
| 内容更新 | 其它非空行作为新标语；内容更新后默认静态显示，过长自动滚动 |
| 弹幕 | 同一行文本同时投递到弹幕通道，取前 24 字符 |

弹幕行为：

- 两条轨道，每条最多 24 字符，2 倍字号（16px 字宽），约 8px/帧自右向左移动
- 新消息先进空闲轨道；两条都占用时只缓存最新一条，等轨道空出后再进场，**旧弹幕一定滚完才消失**
- 每条消息分配一个起始色号，字符颜色按 `(消息色号 + 字符序号)` 取调色板，同一条内逐字变色
- 层3 K2 关闭弹幕时不显示，但标语行仍正常更新

示例（串口助手发送，勾选“加回车换行”）：

```
left
FPGA MULTIMEDIA PLAYER
right
```

## 6. 音频与可视化

- 上电检测到合法 WAV 后自动播放，HDMI 内嵌音频输出；暂停时 I2S 输出静音，FIFO/ASRC 状态冻结
- 自动层 K4 三态循环：0 全关 → 1 音量峰值条 → 2 音量峰值条 + 32 段频谱 → 0
- 视频层 K3 单独打开/关闭频谱（音量条不动）；两处开关是或的关系，任一处打开都显示频谱
- 音量峰值条：峰值保持 + 逐帧缓慢回落
- 32 段频谱：Goertzel 1024 点 Bartlett 窗（约 21.3ms，Q9 系数），每窗清零 s2 累加器；64 个对数 bin 合成 32 段，覆盖约 47Hz~16kHz，幅度按 2.375·log2 映射到 32 级 dB 刻度，静音后两个窗口内归零
- 频谱状态寄存器从 1792 个触发器改为两片 9Kb BRAM（流水线 3 拍/段），节省约 1.2k LUT，是本次时序收敛的关键改动之一

## 7. 视频播放

- 视频层 K1 启动后：`egv_reader` 按段表顺序读扇区 → `video_frame_fill` 做 2 倍放大并写 SDRAM 视频双缓冲（与图片缓冲独立的 BUF2/BUF3）→ 显示侧按 vs 切换
- 视频写口严格 4 拍一字（`step` 门控，约 21M 字/s），一帧 296 行约 11.4ms 写完，远小于 41.67ms 帧周期；**不得去掉 `step` 门控**，否则写口带宽翻 4 倍会把 SDRAM 打满，画面每行前移（横向循环错位）+ 彩色条纹
- 音频与画面共用同一路 EGV 数据流，首帧真正写入 SDRAM 后才放开音频，保证声画对齐
- 视频播放期间 BMP 装载暂停、WAV 让出 SD 总线，SD 读口由视频独占
- 播到容器最后一帧后**自动回卷从第 0 帧继续**（`egv_reader` 的 `LOOP_PLAY=1`）：帧号归零、段指针复位、音频 FIFO 不清空，声画都连续，避免画面停在末帧被误认为卡死；置 `LOOP_PLAY=0` 可回到"冻结末帧 + 等 K1 重播"的旧行为
- 停止视频后回到图片层显示，图片缓冲内容保持不变
