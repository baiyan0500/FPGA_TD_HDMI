# 进度与迭代计划

## 1. 项目目标

在 EG4S20BG256 上实现一个稳定、可现场演示的纯 FPGA HDMI 多媒体播放系统：

- 基础：TF 卡 BMP 播放、SDRAM 帧缓存、HDMI 视频、HDMI 音频、按键交互
- 扩展：字幕 OSD、转场、缩放、实时参数调节、音频可视化
- 交付：可复现的 TD 工程、可用 bit、完整文档、稳定演示流程

## 6. 风险登记

| 风险 | 影响 | 应对 |
|---|---|---|
| Slices 87.0%、Hold 仅 +21ps | 任何 RTL 改动都可能破坏时序 | 每次改动完整重跑；优先用现成 bit；新增逻辑前先看面积（本轮从 4971 超限降到 4219 mslice 才收敛） |
| 视频段表与卡片绑定 | 换卡/换视频后画面错乱或花屏 | 换视频必须重跑 `mp4_to_egv.py`（回填 `egv_cfg.vh`）并重新综合；写入前删除旧容器以免碎片化；单段长度上限 1,048,575 扇区（512MB），超出会被饱和，工具侧需拆段 |
| 普通 Run 必崩 | 无法用默认流程出 bit | 固定使用 Multi-Seed seed 2；`.al` 配置入库 |
| GUI 重置删除运行目录 | 产物丢失 | bit 与 QoR 已备份到 `../../bitstream/`、`docs/reports/` |
| TF 卡物理残留旧图 | 显示旧图/卡死 | 用 `sync_to_sd.py --deep`；仍异常则完整格式化后重同步，换图后断电重启 |
| 视频帧带宽吃紧 | 201 扇区/帧需 37.32ms，预算 41.67ms（余量 10%） | 视频独占期间 WAV 暂停、BMP 让路；不要再给视频层叠加额外 SD 读（弹幕/面板均走内部逻辑） |
| 新 bit 未上板 | 可能存在板级差异 | P0 优先验证，旧 bit 兜底 |
| 长时间运行稳定性未知 | 现场风险 | 30 分钟以上烤机 + 多次上下电 |
