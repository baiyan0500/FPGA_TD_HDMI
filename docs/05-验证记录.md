### 2.5 扫描预算回归修复后复核（check_Runs，MultiSeed seed 2，2026-10-27）

上板现象：烧录 2.4 的 bit 后开机直接显示 `NO IMAGE ON SD`（`i_scan_done=1` 且 `img_count=0`），卡内确有 9 张图 + 1 个 WAV。

根因（读卡原始扇区确认）：该卡为 **exFAT**，`FatOffset=16384`、`FatLength=16384`、`ClusterHeapOffset=32768`（即元数据区占前 16.8MB），第一张 BMP 在扇区 **34048**（17.4MB）。2.4 引入的「连续空档 3072 次 × 4KB = 12MB 即收工」在扇区 24576 就结束扫描，导致一张图都找不到。9 张图依次位于 34048 / 36096 / 38144 / 41728 / 43776 / 47872 / 49920 / 53248 / 55296，WAV 在 57344，全部落在 0~131071 的扫描窗口内，且起始扇区都是 8 的整数倍（4KB 步进不会漏）。

修复：`SD/bmp_read.v` 删除 `MISS_LIMIT/miss_run`，未命中只按 4KB 步进，以 `scan_max_sector`（131071）为唯一边界；`sim/tb_bmp_cycle.v` 增加 `+START=<扇区>` / `+WAVGAP=<扇区>`，用 15MB 空档布局复现 exFAT 卡并回归。

| 指标 | 数值 |
|---|---|
| 仿真（START=30000，15MB 空档） | 9 图全找到 + WAV，18 次切换，`fifo_drop=0`，`errors=0` |
| 仿真 `tb_osd` | `SRCTAG: bad=0`，底栏标注通过 |
| 综合（gate）Setup WNS / FEPs | -416ps / 6 |
| Setup WNS / TNS | **+320ps / 0** |
| Hold WNS / TNS | **+24ps / 0** |
| 违例端点 | 0 / 0 |
| LUT / reg | 14831（75.67%） / 9458 |
| RAM / DSP | 30 / 19 |
| Bit md5 | `ae46dcdcade4a4a8004a07dc8ba59101` |

删掉 12 位 `miss_run` 及其比较器后 LUT 从 14818 降到 14565；同一轮又给 `osd/osd_layer.v` 底栏源尺寸加了前导零抑制（`1024x0577` → `1024x 577`，共 8 个十进制位），LUT 回到 14831。中间还出过一版只含扫描修复的 bit（Setup +83ps，md5 `85da75…`），未上板即被本版取代，已删除。

开机扫描最坏情况扫满 64MB：约 16384 次扇区读 × 164µs ≈ 2.7s；本卡（首图在 34048、WAV 在 57344）实测约 2.2s。旧逐扇区扫描为 21s，2.4 的错误版本 0.5s 但一张图都找不到。

## 4. 已定位的工具问题

TD 6.2.168116 在默认 seed 的 `opt_route` 内建 hold fix 阶段访问违例，退出码 `-1073741819`（0xC0000005），稳定复现。原因是工具为约 70 条短 hold 路径（-3~-20ps）插入缓冲时崩溃，不是 RTL 功能错误。官方 Multi-Seed 在 route 时关闭内建 fix_hold、route 后单独执行 `fix_hold`，可绕过该缺陷。详见 [TD 工程与 Multi-Seed](07-TD工程与MultiSeed.md)。
