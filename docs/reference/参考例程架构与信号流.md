# 两个参考例程：模块架构 + 信号流 + 时钟/复位域清单

> 用途：为「合并两个例程 + 叠加赛题加分项」提供一张可施工的图纸。
> 参照对象：`lab_ex4_tf/`（纯视频版）与 `lab_ex5_i2s/`（视频+音频版）。
> 所有端口名、参数值、时钟频率均从源码与 `.ipc` 中直接提取，非推测。

## 1. 时钟与复位域总表

三个 PLL 全部由板上 **50 MHz** 有源晶振（`clk`，引脚 R7）驱动。

| PLL 实例 | 输出网络名 | 频率 | 相位 | 用途 | 来源 `.ipc` |
|---|---|---|---|---|---|
| `sys_pll_m0` | `sd_card_clk` | **100 MHz** | 0° | TF 卡 SPI + BMP 解析 + 卡侧状态机 | `IP/sys_pll.ipc` |
| `sys_pll_m0` | `ext_mem_clk` | **125 MHz** | 0° | SDRAM 控制器与帧缓存调度 | 同上 |
| `sys_pll_m0` | `ext_mem_clk_sft` | **125 MHz** | 180° | SDRAM 时钟移相（供控制器内部采样） | 同上 |
| `video_pll_m0` | `video_clk` | **25 MHz** | 0° | 像素时钟、显示时序、**I2S 接收与 ACR 计算** | `IP/video_pll.ipc` |
| `video_pll_m0` | `hdmi_5x_clk` | **125 MHz** | 0° | TMDS 10:1 串行化时钟（= 25 MHz × 5） | 同上 |
| `u_audio_pll` | `audio_mclk` | **12.288 MHz** | 0° | **仅 lab_ex5**：I2S 主时钟（测试音发生器） | `td_project/al_ip/PLL_HDMI_AUDIO.ipc` |

> `u_audio_pll` 另有两个未使用的输出：clk0 = 75 MHz、clk1 = 375 MHz @90°（对应 `.ipc` 里的 id 0 / id 1）。

**复位域**

| 例程 | `rst_all` 生成方式 | 评价 |
|---|---|---|
| **lab_ex4_tf** | `clk` 域 POR 状态机：`sys_pll_lock && video_pll_lock` 连续稳定 **20 ms**（1,000,000 × 50 MHz）后释放；释放后**锁存**，不再理会后续 PLL 抖动 | ✅ 更稳，推荐 |
| **lab_ex5_i2s** | `assign rst_all = ~rst_n \| ~audio_pll_lock;` 纯组合 | ⚠️ 缺 video_pll 锁定判断，无防抖 |

`rst_all` 是**唯一的全局复位**，跨所有时钟域异步释放（各模块内部自行同步）。

**一句话**：①TF 卡（100 MHz 域）→ ②SDRAM 帧缓存（125 MHz 域）→ ③显示时序 + 帧读出（25 MHz 域）→ ④HDMI 发射核 → ⑤TMDS 物理层。音频 `[A]` 是一条**并行支路**，在 ④ 处汇入视频流。

**关键接口（`bmp_read` ↔ `sd_card_bmp`）**

```
bmp_read 输出： ready / scan_start / load_start / sd_sec_read{,_addr,_data,_data_valid,_end}
              bmp_data_wr_en + bmp_data[23:0]  ← 每像素一拍，24 bit RGB
              state_code[3:0]（送数码管）
```

**像素打包（重要）** —— [sd_card_bmp.v:77](../../../reference/lab_ex5_i2s/src/user_source/hdl_source/SD/sd_card_bmp.v#L77)：

```verilog
assign write_data = {bmp_data[23:16], bmp_data[15:8], bmp_data[7:0], 8'b0};
```

即 **一个像素占一个 32 bit 字，RGB 在 `[31:8]`，低 8 位恒为 0**。读出侧据此用 `read_data[31:8]`（见 `video_delay` 例化）。**后续做 OSD/缩放时，任何图层都必须遵守这个格式。**

**BMP 格式硬约束**：640×480、24 bit、非压缩（`bmp_read` 只认这一种）。

**防死锁**：lab_ex5 无；lab_ex4 有（见第 6 节）。

| ↳ `sdr_wrrd` | [include/sdr_wrrd.enc.v](../../../reference/lab_ex5_i2s/src/user_source/hdl_source/include/sdr_wrrd.enc.v) | 读写时序引擎（加密） |

**用户侧四线握手**（贯穿整条缓存链）：

```
写： write_req ──► write_req_ack ──► write_en / write_data[31:0] ──► write_finish（单拍）
读： read_req  ──► read_req_ack  ──► read_en  ──► read_data[31:0]（下一拍有效）
```

**`WRITE_V_FLIP` 的作用**：BMP 文件是**自底向上**存储的（第 0 行在文件末尾），翻转后 SDRAM 内变成自顶向下，显示端才能顺序读出。**做缩放/裁剪时不要丢掉这个翻转语义。**

**地址映射**：`App_*_addr` 为 21 bit（`ADDR_WIDTH=21`），控制器按 `{row[10:0], bank[1:0], col[7:0]}` 解释，突发长度 256 字（`BURST_SIZE=256`）。

**视频时序参数**（`color_bar` 的 `VIDEO_640_480` 分支）：

```
H_ACTIVE 640  H_FP 16  H_SYNC 96  H_BP 48   → HTOTAL 800
V_ACTIVE 480  V_FP 10  V_SYNC  2  V_BP 33   → VTOTAL 525
HS_POL 0 (负极性)   VS_POL 0 (负极性)
```

与顶层 HDMI 核参数（`HTOTAL=800 / HSA=96 / HFP=16 / HBP=48 / VTOTAL=525 / VSA=2 / VFP=10 / VBP=33 / VIC=1`）**完全一致**。

→ 25 MHz / (800×525) = **59.52 Hz** 场频。

> `video_delay` 的 21 级延迟是**为了对齐 SDRAM 读通路（异步 FIFO + 突发预取）的固有延迟**。任何插入到 `vout_data` 与 HDMI 核之间的模块（OSD、缩放、转场）**必须自行补偿自己的流水线延迟**，否则画面会与 `de/hs/vs` 错位。

| `AUDIO_SAMPLE_ROM` | `td_project/al_ip/AUDIO_SAMPLE_ROM.v` | — | 上述 ROM 播放器的采样存储器 |

**I2S 时序（从源码反推）**

```
audio_mclk = 12.288 MHz
BCLK = audio_mclk / 2      = 6.144 MHz   （每个 mclk 拍翻转一次）
每声道 64 个 BCLK 槽位，LRCK 每 64 个 BCLK 翻转 → LRCK = 48 kHz
采样字长 24 bit，MSB first，左对齐占满 [63:40]
```

**ACR 计算原理（[audio_arc_calculate.v](../../../reference/lab_ex5_i2s/src/user_source/hdl_source/audio_arc_calculate.v)）**

```
ACR_N = 6144,  AUDIO_DIV = N >> 7 = 48
每收到 48 个 audio_valid（= 48 个音频采样）→ 发一次 acr_valid
同时把该窗口内 video_clk 的拍数作为 CTS 输出
```

校验：`48 / 48000 s × 25 MHz = 25000` 拍 → `N/CTS = 6144/25000 = 0.24576`，而 HDMI 要求 `128×fs / f_pixel = 128×48000 / 25e6 = 0.24576` ✅ 吻合。

> **副产品**：因为 `CTS` 是**实测**的（不是写死的常数），改变像素时钟（例如后续上 800×600）时该比值会自动跟随。`N=6144` 无需改动 —— 但仍建议上板后用示波器/电视实测确认声音正常。

**音频链路的跨时钟域**：I2S 三线在 `audio_mclk` 域产生，接收端在 `video_clk` 域采样（25/6.144 ≈ 4.07 拍/BCLK）。`I2S_receiver` 内用 **3 级同步器 + 边沿检测**处理（`S_i2s_bclk_1d/2d/3d` → `S_i2s_bclk_p_edge`）。**这是本设计里最"紧"的 CDC**，改视频时钟时必须重新核对。

## 4. 跨时钟域（CDC）边界清单 ⚠️ 改造时最易踩坑

| # | 信号 | 从 | 到 | 同步方式 | 状态 |
|---|---|---|---|---|---|
| 1 | 像素数据 + 写使能 | `sd_card_clk` 100 M | `ext_mem_clk` 125 M | `wfifo_32_32_512` 异步 FIFO | ✅ 规范 |
| 2 | 像素数据 + 读使能 | `ext_mem_clk` 125 M | `video_clk` 25 M | `rfifo_32_32_512` 异步 FIFO | ✅ 规范 |
| 3 | `frame_write_finish` → `frame_write_toggle_mem` | `ext_mem_clk` 125 M | `sd_card_clk` 100 M | 先转 toggle，再在 `sd_card_bmp` 内 `wrfin_tgl_sync[2:0]` **3 级同步** | ✅ 规范 |
| 4 | `I_i2s_BCLK/LRCK/DOUT` | `audio_mclk` 12.288 M | `video_clk` 25 M | `I2S_receiver` 内 3 级同步 + 边沿检测 | ⚠️ 频率比仅 ~4:1，最紧 |
| 5 | `sys_pll_lock` / `video_pll_lock` | PLL | `clk` 50 M POR 状态机 | 电平采样（PLL lock 本身已同步） | ✅ 可接受 |
| 6 | `audio_pll_lock` | PLL | 组合进 `rst_all` | **无同步**（直接组合） | ⚠️ lab_ex5 可改进点 |

> 第 3 条的 3 级同步器在 [sd_card_bmp.v:167](../../../reference/lab_ex5_i2s/src/user_source/hdl_source/SD/sd_card_bmp.v#L167)：
> `wrfin_tgl_sync <= {wrfin_tgl_sync[1:0], write_finish_toggle};`

## 5. SDRAM 地址空间分配

```
ADDR_WIDTH = 21 bit  →  2,097,152 字 × 32 bit = 8 MB
FRAME_PIXELS = 307,200 (= 640 × 480)

BUF0_ADDR = 0            ← 缓冲 A：[0, 307200)
BUF1_ADDR = 307,200      ← 缓冲 B：[307200, 614400)

已用：614,400 / 2,097,152 字 = 29%
余量：可再容纳 4 个满帧
```

**余量的用途（后续切分建议）**
- 再加一组双缓冲 → 做"预加载下一张图"的三缓冲，转场时可随时取用
- 划出一块常驻 **OSD 图层帧缓存**（例如 640×480 的 1 bit 掩码，仅需 38,400 字 = 1.8%）
- 划出两块小图缓存做缩放源

## 6. `lab_ex4_tf` vs `lab_ex5_i2s` 逐项差异

### 6.1 文件级差异

| 类别 | 内容 |
|---|---|
| **仅 lab_ex5 有（HDL）** | `I2S_receiver.v`、`audio_arc_calculate.v`、`hdmi_audio_tone_i2s_64fs.v`、`hdmi_audio_tone_pcm_scale.v` |
| **仅 lab_ex5 有（IP）** | `PLL_HDMI_AUDIO`、`AUDIO_SAMPLE_ROM` |
| **仅 lab_ex5 有（资源）** | `python/`（wav↔mif 工具 + 采样数据）、`rom/`、`test/`（两个 I2S 自测顶层） |
| **两边都有但内容不同** | `top_tf_hdmi_audio.v`、`IP/sys_pll.v`、`IP/video_pll.v`、`SD/bmp_read.v`、`SD/sd_card_bmp.v`、`pin.adc`、`timing.sdc` |
| **仅注释/空白差异** | `SD/seg_decoder.v`、`SD/seg_scan.v`（功能完全一致） |
| 其余全部文件 | **逐字节相同** |

### 6.2 功能差异（**结论：两个都不是超集**）

| 能力 | lab_ex4_tf | lab_ex5_i2s |
|---|---|---|
| TF 卡 BMP → SDRAM → HDMI 视频 | ✅ | ✅ |
| 双缓冲无缝切图 / key1 手动 / key2 自动轮播 | ✅ | ✅ |
| HDMI 音频输出 | ❌（音频端口接 0） | ✅ |
| **POR 复位（等两个 PLL 各锁 20 ms）** | ✅ | ❌（只看 audio PLL） |
| **SD 卡读取 1 秒超时防死锁** | ✅ | ❌ |
| **`write_done_seen` 写法（防"先写完后源结束"丢脉冲卡死）** | ✅ | ❌ |
| 按键消抖时长 | 50 ms | 20 ms |
| `sys_pll`/`video_pll` 是否引出 `extlock` | ✅ 引出 | ❌ 接 `open`（**POR 无法实现的直接原因**） |
| 顶层 `key1/key2/rst_n` 上拉 | ✅ `PULLTYPE = PULLUP` | ❌ 无 |

### 6.3 lab_ex4 独有的三处鲁棒性改进（细节）

**(1) POR 复位** —— [lab_ex4 top:105-129](../../../reference/lab_ex4_tf/src/user_source/hdl_source/top_tf_hdmi_audio.v#L105-L129)

```verilog
always @(posedge clk) begin
    if (!rst_n) begin rst_cnt <= 0; rst_all_reg <= 1'b1; end
    else if (!rst_all_reg) rst_all_reg <= 1'b0;      // 锁存：释放后不再复位
    else if (sys_pll_lock && video_pll_lock) begin
        if (rst_cnt < 20'd1_000_000) begin rst_cnt <= rst_cnt + 1; rst_all_reg <= 1'b1; end
        else rst_all_reg <= 1'b0;                     // 20ms @50MHz
    end else begin rst_cnt <= 0; rst_all_reg <= 1'b1; end
end
```

**(2) SD 读取防死锁** —— `sd_card_bmp.v` 中的 `load_timeout_cnt` / `load_abort`，超时阈值 `32'd100_000_000`（1 s @100 MHz）。超时后强制释放 `load_busy` 并拉高 `load_abort`；`bmp_read` 相应新增 `load_abort` 输入端口用于退出。

**(3) 提交条件改为电平锁存** —— lab_ex5 用单拍脉冲 `write_finish_pulse` 做提交条件，若"整帧先写完、源文件后读完"则该脉冲已丢失 → **卡死**；lab_ex4 改用 `write_done_seen` 电平记忆：

```verilog
if (load_busy && write_finish_pulse) write_done_seen <= 1'b1;
if (load_busy && source_done_seen && write_done_seen) begin ... 提交 ... end
```

> **合并方向明确**：以 **lab_ex5_i2s 为基底**（它有必需的音频链路），把 lab_ex4 的 **(1)(2)(3)** 三处改进移植过来。移植 (1) 时必须**同时替换 `IP/sys_pll.v` 和 `IP/video_pll.v`**（lab_ex4 版本引出了 `extlock` 端口），否则 `sys_pll_lock` 无从取得。

## 8. 改造切入点（对应赛题 5 个加分项）

| 加分项 | 推荐插入位置 | 具体理由 |
|---|---|---|
| **(1) 图层叠加 / 字幕** | `vout_data` → `video_rgb_to_axis` **之间** | 此时是干净的 24 bit RGB + 对齐的 `de`；新增一个 `layer_mixer` 即可。字符点阵可参考 `Other/25_seg70_small16x16` |
| **(2) 转场特效（淡入淡出/滑动）** | `frame_read_write` 的**读地址生成** 或 `vout_data` 后 | 淡入淡出：在两块帧缓存读出结果上做加权（需同时读 A/B 缓冲，或先在 SDRAM 内合成）；滑动：改 `video_delay` 的读地址偏移 |
| **(3) 图片缩放** | 替换固定的 `FRAME_PIXELS` 读通路 | 当前读写长度写死 307200，需改为"按源分辨率读 + 插值到 640×480"。双线性插值需要跨行缓存（用片上 ERAM9K）：`64 块 9Kb + 16 块 32Kb`，够放几行 |
| **(4) 实时参数 + OSD** | 按键 → `seg`/OSD 图层；亮度对比度在 `layer_mixer` 内做 | 板上有 **4 按键 + 4 拨码**，例程只用了 2 个按键；剩余 2 键 + 4 拨码可直接用 |
| **(5) 音频可视化** | 在 `I2S_receiver` 的 `O_audio_left/right_data` 上**分叉**一条支路 | PCM 已经现成；接一个峰值检测/简易频谱（Goertzel 或 FIR 组）→ 画成柱状图叠到 OSD 层 |

**公共前提**：任何插入到视频通路的模块，都必须**同步延迟 `hs/vs/de`**（参照 `video_delay` 用移位寄存器对齐的做法），否则画面撕裂/错位。

## 9. 待现场确认事项

1. **HDMI 连接器命名**：官方 lab_ex4/lab_ex5 文档说用 **HDMI_B**，但 `pin.adc` 里的引脚组是 `C3/G5/F1/E1` —— 而 `Other/31_hdmi_tx_display_A` 用的**也是**这组引脚，且额外声明了另一组 `K1/F5/E3/B3`（命名为 `*_P1`）。**引脚才是事实，A/B 标签在两个来源间不一致，请上板核对后再下结论。** 若要做双 HDMI 输出，`K1/F5/E3/B3` 就是第二路（需再例化一套 `hdmi_phy_wrapper`）。
2. **`sys_pll`/`video_pll` 的 `extlock`**：lab_ex5 的 IP 已把该端口接 `open`。移植 POR 时务必确认改用 lab_ex4 版本的 IP 文件（或按 `.ipc` 在 TD 里重新生成）。
3. **音频实际采样率**：`AUDIO_SAMPLE_RATE="48K"`、`ACR_N=6144`、`audio_mclk=12.288 MHz` 三者自洽，但**上板后需实测**电视是否稳定出声。
4. **TF 卡图片**：必须 640×480 / 24 bit / 非压缩 BMP。用 [doc/convert/sync_to_sd.py](../../../reference/lab_ex4_tf/doc/convert/sync_to_sd.py) 同步（直接删卡上旧图会残留物理扇区导致读错）。
